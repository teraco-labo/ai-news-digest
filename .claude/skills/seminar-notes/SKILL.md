# セミナー録画から議事録を作る

`seminar_notes.py` を代わりに動かして、ユーザーがコマンドを打たずに済むようにするためのスキル。
ユーザーはターミナルを触りたくないので、**こちらが実行して、結果を会話の中に出す**。

## 前提

- スクリプトはリポジトリ直下の `seminar_notes.py`
- 出力は `seminars/<スラッグ>/` に `transcript.txt` / `notes.md` / `meta.json`
- 詳しい仕様は `SEMINAR_NOTES.md`。仕様で迷ったらそちらを読む

## 初回だけのセットアップ

ユーザーが自分のMacでこのリポジトリを開いた直後は、依存パッケージが入っていない。
「準備して」と言われたとき、あるいは実行してパッケージ不足のメッセージが出たときは、
聞き返さずにこちらで済ませる。ユーザーはターミナルを触りたくないので、
「これを実行してください」と手順を渡すのは最後の手段。

```bash
python3 -c "import youtube_transcript_api, yt_dlp, anthropic, dotenv" 2>&1   # 足りないものを確認
python3 -m pip install -r requirements.txt                                   # 足りなければ入れる
command -v whisper || brew install openai-whisper                            # 音声から起こす用
```

字幕が無い録画（Zoomのローカル録画など）は、**Mac の中の `whisper` で文字起こしする**。
鍵も費用も要らず、音声が外に出ない。セミナーは社外に出せない内容が多いのでこれが既定。
**鍵を要求しないこと。** 代わりに時間がかかる（録画の長さとだいたい同じ）ので、
実行前に「1時間の録画なので1時間弱かかります。裏で走らせます」と必ず伝える。

`--cloud-transcribe` を使うのは、ユーザーが**急いでいると明言したときだけ**。
その場合は `GEMINI_API_KEY` が要ること、費用がかかること、**音声が Google に渡ること**を
3点セットで伝えてから使う。社外秘の録画では勧めない。

## 新しい録画をまとめるとき

### 1. 必要なものを揃える

要るのは **録画の場所**（URL・ファイルパス・Zoom の会議ID）と **セミナー名** の2つだけ。

**録画が Zoom のクラウドにあるなら、そこから直接取るのが一番いい。**
YouTube にアップし直す手間が要らず、AIに文字起こしさせる費用もかからず、
なにより **Zoom の文字起こしには話者名が入る**（誰の発言かが残ると、議事録の
ネクストアクションに担当者が埋まる）。ユーザーが「Zoomで録画した」と言ったら、
URL を聞く前に `--zoom-list` を試すこと。

セミナー名を言われていない場合、URL からタイトルが取れることは期待できないので、
一度だけ短く尋ねる。「何の会でしたか？（議事録の見出しに使います）」程度でよい。
ユーザーが「なんでもいい」と言ったら日付から `2026-08-27の勉強会` のように決めて先に進む。
ここで質問を重ねて足止めしないこと。ユーザーはラクをしたくてこのスキルを呼んでいる。

### 2. 実行する

```bash
python3 seminar_notes.py "<URL またはファイルパス>" --title "<セミナー名>"
```

Zoom のクラウド録画のときは、まず一覧を出して**どれかをユーザーに選んでもらう**。
一覧には日時・会議名・長さ・文字起こしの有無が出るので、そのまま会話に貼れば選べる。

```bash
python3 seminar_notes.py --zoom-list                       # 直近30日
python3 seminar_notes.py --zoom-list --zoom-days 90        # 見つからなければ広げる
python3 seminar_notes.py --zoom "<会議ID>" --title "<セミナー名>"
```

Zoom の3点セット（`ZOOM_ACCOUNT_ID` / `ZOOM_CLIENT_ID` / `ZOOM_CLIENT_SECRET`）が
`.env` に無いときは、設定を求める前に**設定なしで済む道**を先に出す。Zoom のウェブ画面から
「音声文字起こし」の VTT ファイルを落として渡せば、それだけで議事録まで進む。
毎回やるのが面倒だと言われて初めて、鍵の作り方（→ `SEMINAR_NOTES.md`）を案内する。

文字起こしが既にある場合（YouTube の「文字起こしを表示」からコピーしたテキストを
ユーザーが会話に貼ってきた場合も含む）は、それをファイルに保存して渡すのが一番速い。
`.txt` `.vtt` `.srt` を受け付ける。

```bash
python3 seminar_notes.py "<文字起こしファイル>" --title "<セミナー名>"
```

ユーザーが「ここを重点的に」と言っている場合は `--focus` にそのまま渡す。

```bash
python3 seminar_notes.py "<URL>" --title "<名前>" --focus "ツールの使い方を手順まで詳しく"
```

ツールやサービスの操作説明が中心の回（インストール手順・設定画面・プラン比較など）は
`--focus` を付けなくても「ツールの使い方」セクションが出るようになっているが、
ユーザーがそこを求めていると分かっているなら明示的に渡したほうが厚く書かれる。

長い録画だと文字起こしと議事録生成で数分かかる。実行前に
「文字起こしと議事録の作成で数分かかります」と一言添えておくと、待たせても不安にさせない。

### 3. 結果を会話の中に出す

**ファイルの場所を伝えて終わりにしない。** ユーザーはターミナルを開きたくないので、
`notes.md` を読んで、中身をそのまま会話に出す。出す順番は:

1. **タイムスタンプ付き要約** — 全文。これが一番よく使われる
2. **ツールの使い方**（あれば）— 全文。操作手順の回では、ここが一番の成果物になる。
   長さを理由に省略しない
3. **決まったこと** と **ネクストアクション** — 短いので全文
4. 議事録の本体は長いので「議事録の本文も出しますか？」と聞くか、
   ファイルの場所だけ添える

最後に、次にできることを1〜2行で示す。

- 配布メールの文面ができていること（`notes.md` の末尾）
- 内容について質問できること（例を1つ挙げる。「MCP版とAPI版の違いは？」など）
- NotebookLM を使いたいなら `transcript.txt` を貼り付ければソースにできること
- **YouTube の自動字幕から作った場合は、人名が聞き取り違いで崩れていることが多い。**
  配布前に名前を直す必要があることを、こちらから先に言う（Zoom の文字起こしなら正しく入る）

### 4. 失敗したとき

エラーメッセージをそのまま貼らない。原因と次の一手を日本語で伝えて、
可能ならこちらでリトライする。

| 出た症状 | 原因 | 次の一手 |
|---|---|---|
| 字幕APIでも yt-dlp でも取れない | 動画に字幕が無い | `--audio` を付けて音声から文字起こしを試す。`GEMINI_API_KEY` が無ければそれを伝える |
| ダウンロードが 403 / ログインが要る | 限定公開＋要ログイン | `--cookies-from-browser chrome` を足して再実行する。ブラウザ名はユーザーに確認する |
| 3つの経路すべてが 403 / ProxyError で落ちる | 実行環境が YouTube への通信自体を遮断している | ユーザーの設定ミスではないことを先に伝える。YouTube の「文字起こしを表示」からコピーして貼ってもらい、それをファイルに保存して渡す（下記）。この経路なら通信は要らない |
| Zoom の録画が一覧に出ない | 期間が足りない／クラウド録画ではない | `--zoom-days 90` で広げる。それでも無ければローカル録画の可能性を尋ねる |
| Zoom に文字起こしが無い | 有料プランの「音声文字起こし」がオフ | 音声から起こすので `GEMINI_API_KEY` が要ることを、理由とセットで伝える |
| 議事録だけできない | Claude を呼べていない | 文字起こしは保存済みなことを伝える。`claude` CLI のログイン状態か `ANTHROPIC_API_KEY` を確認してもらう |
| 「未インストールなのでスキップします」が出る | 依存パッケージが入っていない | `python3 -m pip install -r requirements.txt` をこちらで実行してから、やり直す |

## 一覧を見せてと言われたとき

「一覧見せて」「どんな議事録あったっけ」と言われたら、**2つセットで返す**。

```bash
python3 seminar_notes.py --list
```

1. `--list` の結果を会話の中に出す（開催日・タイトル・分量が分かる形で）
2. **`seminars/index.html` を SendUserFile の `display: "render"` で送る**。
   右のパネルでそのまま開けて、各回へのリンクもたどれる

ユーザーにファイルパスを渡して「開いてください」で終わらせない。
ターミナルを触らずに済むことが、このスキルの存在理由。

## 過去の録画に質問されたとき

「あの勉強会で料金の話どこだっけ」のように中身を尋ねられたら、記憶や推測で答えない。
文字起こしを根拠に答えるために `--ask` を使う。

```bash
python3 seminar_notes.py --list                          # どれのことか分からないとき
python3 seminar_notes.py --ask "<質問>" --slug <スラッグ>   # 特定の回を指定
python3 seminar_notes.py --ask "<質問>"                   # 直近の回でよければ
```

回答にはタイムスタンプが付いて返ってくる。**そのタイムスタンプを消さずに**ユーザーに見せる。
「何分のところを見ればいいか」が分かることが、この機能の価値そのものだから。

どの回か特定できないときは、`--list` の結果を見せて選んでもらう。

## 配布メールまで頼まれたとき

`notes.md` の末尾に、そのまま送れる文面がある。議事録URL・録画URLはプレースホルダに
なっているので、ユーザーに聞いて差し込む。

Gmail が使える環境なら、**下書きの作成までは進めてよい**（`create_draft`）。
ただし送信は別の話なので、勝手に送らない。「下書きを作りました。宛先と本文を確認して
送信してください」と渡すところで止める。誰に送るかはこちらには分からないし、
セミナーの内容は社外に出せないことが多い。

## 相談として聞かれたとき

「NotebookLM が YouTube を読んでくれない」のように、作業依頼ではなく相談の形で
来ることがある。そのときは原因を短く説明してから、このツールで解決できることを伝える。

原因は毎回同じで、NotebookLM は **一般公開＋字幕あり＋投稿から72時間経過** の動画しか
読み込めず、しかも**動画を文字起こしせず YouTube の字幕データを取り込んでいるだけ**だから。
限定公開のセミナー録画はこの条件から外れる。回避策は「文字起こしをテキストとして渡す」で、
それがこのツールの `transcript.txt` にあたる。

説明は3〜4行で足りる。長々と講義しないこと。
