# セッションの引き継ぎメモを作る

このセッションで起きたこと・決めたことを `SESSION_HANDOFF.md`（リポジトリ直下）に
まとめ、GitHubにプッシュして、**別のセッションが読めば続きから始められる状態**にする。
ユーザーは非エンジニアなので、こちらが全部実行して、最後に「新しいセッションへの
最初のひとこと」まで渡す。

## 手順

1. **材料を集める**
   - このセッションの会話をふり返り、次を洗い出す：
     やったこと／決めたこと（ユーザーの言葉が根拠なら原文も）／
     ハマった罠と対処／未完了・返事待ちの項目／変えてはいけない約束事
   - `git log --oneline -20` で、このセッション中のコミットも確認する

2. **`SESSION_HANDOFF.md` を更新する**
   - すでにあるファイルを**上書き更新**する（新しいファイル名にしない。
     引き継ぎ先が迷わないよう、場所は常にリポジトリ直下のこの1ファイル）
   - 冒頭の日付を今日に更新する
   - 既存の章立てを保つ：目的／いまの状態／設計の核／やりとりのルール／
     主なファイル／ハマりどころ／残っている作業／使わなくなったもの
   - 古くなった記述は消すのではなく直す。**まだ生きている約束事
     （二層構造の原則・プレビュー2点セット提示・課金記録など）は絶対に消さない**

3. **GitHubに保存する**
   - 毎朝6時の自動更新でリモートが先に進んでいることが多いので、
     必ず `git fetch origin main` → `git rebase origin/main` してからプッシュする
   - コミットメッセージは日本語で「なぜ」を書く（例：
     `docs: 引き継ぎメモを更新（◯◯の作業をまとめた）`）

4. **ユーザーに渡す**
   - 完了報告と一緒に、新しいセッションの最初に貼ってもらう文面を渡す。例：
     > まず `SESSION_HANDOFF.md` と `CLAUDE.md` を読んでから始めてください
   - GitHub上のファイルURLも添える：
     https://github.com/teraco-labo/ai-news-digest/blob/main/SESSION_HANDOFF.md

## 書き方の注意

- 読み手は**別のClaude**なので技術的に書いてよいが、ユーザーも読むので
  極端な略語やコード断片の羅列は避ける
- 「何をしたか」より「**なぜそう決めたか**」を優先して残す。
  半年後・別セッションでも判断の理由が分かることが基準
- ユーザー側の作業待ち項目（アカウント登録など）は表にして残す。
  引き継ぎ先が「次に何を聞けばいいか」すぐ分かるようにする
